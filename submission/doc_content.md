## AI 工具辅助游戏创作过程说明

### 项目背景

我是完全的游戏开发小白 —— 既没用过游戏引擎，也没系统学过物理和图形。我有的只是：一台 Mac、一周时间、对真实飞盘高尔夫物理的好奇心，以及 Claude Code 作为协作搭档。

这个项目就是我和 Claude Code 用一周时间做出来的飞盘高尔夫游戏，包含：

- 真实物理模拟（升力分解 + bank 演化 + 陀螺进动）
- 13 个原创关卡（含森林、湖泊、硬地、风分区、传送门等机制）
- 完整 meta-game（标题菜单、关卡选择、成绩持久化、教学卡片）
- 程序化合成的所有音效（无任何外部素材）

### 场景 1 ─ 物理建模：从"看着像"到"真的对"

最初版本用简单的"侧向力"模拟弯曲，但玩家投出来感觉像石头抛物线。我把感受告诉 Claude Code，它解释了真实物理：**飞盘是陀螺，倾斜后升力会同时承担"对抗重力"和"让轨迹弯曲"两个职能**。这一句话改变了整个引擎设计。

最终物理模型有 4 个状态量：

- `disc_pos` 平面位置
- `disc_height` 真实高度（带重力）
- `disc_vz` 垂直速度
- `disc_bank` 倾斜角（实时演化）

每帧 6 步：升力大小 → 升力分解（垂直 cos / 水平 sin × spin_sign）→ 重力高度积分 → Bank 力矩（turn / fade / 自然回归）→ 风 → 阻力。

涌现行为（不需要专门写代码就自动出现）：

- **Hyzer-flip**：不稳定盘 + hyzer 出手 → 自动翻平 → 飞最远
- **Spike hyzer**：大角度倾斜 → 升力被分走 → 快速落地不滚
- **平投飞最远**：bank=0 时 100% 升力垂直 → 滞空最久
- **正反手镜像**：spin_sign 翻转 → S 曲线方向反转

#### 协作过程的关键对话节选

> 我："你的弧线感觉就是一个抛物线，但是飞盘的飞行弧线不是这样"
>
> Claude："你说的对…真实飞盘是平飞滑翔很久才掉，像滑翔机不像石头。问题在于 lift 加速度太大形成抛物线，应该让 lift ≈ gravity 在中高速段…"

这种"我描述感受 → AI 推回根因 → 我们一起调"的循环是整个项目最高效的协作模式。

### 场景 2 ─ 关卡机制设计：从抽象到具体

我用自然语言描述关卡感觉，Claude Code 翻译成数据结构。

**例 1 传送门关**

> 我："Portal 关，地图上某些区域是传送圈，盘飞过会瞬移到另一处。"
>
> Claude 实现：`class Portal { pos, radius, dest, pair_color }`，加上 0.4s 冷却避免穿梭振荡，绘制配对色彩圆环。

**例 2 强制门关**

> 我："Mandatory，地图上一根红线，盘必须从某一侧通过否则 +1 罚杆。"
>
> Claude 实现：`class Mando { p1, p2, required_side, label }`，每帧叉积判断盘当前在哪一侧，落地时检查是否经过指定侧。

**13 关清单**：

| # | 关名 | 核心机制 |

| 1 | Practice Park | 入门 |
| 2 | Grassland | 风分区（顺/侧/逆）|
| 3 | Forest | 树丛绕行 |

| 5 | Hard Ground | 硬地滚动 |
| 6 | Boomerang | 环形布局 |
| 7 | Multi-Lane | 多路径选择 |

### 场景 3 ─ Bug 调试：人发现，AI 找根因

**例：进筐弹出概率异常**

> 我："明明看着轨迹是中心，但是 mid 的弹出率还是高得吓人，检查下偏心是不是算错了。"
>
> Claude 立刻反应过来："飞盘进入捕获圆瞬间，位置正好在圆边缘，偏心率 = 1.0。我一直在用'当前位置距筐心'算偏心，应该用'飞行轨迹到筐心的垂直距离'。"
>
> 一行代码改完：`perp_dist = |to_basket × forward|`，bug 消失。

类似的 debug 还有：

- Q/E 不对称（turn_torque 符号反了）
- 撞树后玩家被卡死（反弹距离从 8px 增到 30px）
- Level 10 全部判罚（_surface_at 早返回逻辑错误）
- 第二关力度条丢失（被相机变换"吸走"了，需移到 HUD 层）

### 场景 4 ─ 玩家体验细节

很多看不见但能"感觉到"的细节：

- **飞行/滚动视觉分离**：飞行时盘抬起来 + 阴影投影，滚动时盘"压扁"成线 + 棕色尾迹
- **离屏筐指示器**：相机不在筐位置时屏幕边缘显示箭头 + 距离
- **正反手出手点偏移**：BH 在玩家左侧出手，FH 在右侧 —— 视觉上立刻看出区别
- **声音全程序化合成**：throw / chain / land / tree / rim / splash / roll 全用 PackedFloat32Array 写出来的，零外部资源

### 这个项目证明了什么

1. **AI 不是替代而是放大器**。我没有变成游戏开发专家，但 Claude Code 变成了我的游戏开发副驾驶 —— 我决定方向，它写代码 + 解释原理 + 帮我 debug。
2. **真实感来自物理，不是美术**。游戏全是 `draw_*` 原语画的色块，没有任何 sprite。但因为物理对，玩起来就有"飞盘味"。
3. **文档和代码同等重要**。每一次决策都写下来，让下一次会话能无缝接上 —— 这是 AI 协作时代的"git"。
