# v0.3 — Re-design Document

> Status: **proposal**. No code changes yet. Awaiting approval before implementation.

## 1. Honest Review of v0.2

### What works

- **State machine** is clean: Title → Tutorial → Playing → Hole Complete → Round Complete.
- **Tutorial as 5 standalone cards** with illustrations — survives any gameplay edge case.
- **Flight model** correctly produces hyzer/turn/fade shapes; physics is the strongest part of the project.
- **BH/FH** distinction is implemented (range × jitter × mirrored spin).
- **Wind** is per-hole, visualized, late-flight bias correct.
- **Procedural SFX** with no external assets — surprisingly serviceable.

### What's broken or weak (user feedback + my own audit)

| Issue | Why it matters | Severity |
|---|---|---|
| **No distance tiers** (putt/mid/huck) | All throws scale linearly with drag — no strategic depth | High |
| **BH/FH model too one-dimensional** | Real difference depends on *distance*, not a constant +22% | High |
| **Hyzer Q/E visual feedback is subtle** | Small cyan dot on a bar — players miss it | High |
| **No release-point visual for BH/FH** | The two hands look identical | High |
| **Hole = bounded screen** | Feels like a tech demo, not a course | High |
| **Only trees as obstacles** | No water / rocks / OB → no risk-reward layer | High |
| **No basket spit-out** | Hot drives shouldn't auto-catch | Medium |
| **Viewport 1280×720** | Cramped on modern Macs | Medium |
| **No predicted curve in aim** | Player can't preview what hyzer/disc combo will do | Medium |
| **Aim preview is straight line** | Misleads — actual flight curves | Medium |

## 2. New Domain Knowledge to Encode

From your latest input (key real-world rules we were missing):

1. **Distance tiers govern style**:
   - **Dump / Putt (<20m)**: wrist-only, BH dominant (~90% of putts), very accurate, short.
   - **Mid (20–50m)**: BH and FH roughly equal in accuracy; player preference.
   - **Huck (>50m)**: BH = max range; FH = better accuracy than BH at this range.
2. **Wind effects**:
   - Tailwind → farther flight
   - Headwind → shorter, often dropped
   - Crosswind → flat (non-spinning-on-the-correct-axis) discs drift sideways
3. **Basket spit-out**: discs hitting the basket too hot deflect out.

This is the heart of v0.3.

## 3. v0.3 Core Design

### 3.1 Throw style matrix (the big rewrite)

We add a **mode** dimension: *Putt / Mid / Huck*. Each mode × hand combination
has its own accuracy + range characteristics, calibrated to the real-world rules.

Mode is **auto-selected from drag length** so casual play stays single-input,
but the HUD shows the current mode prominently (and the player can override
with `Z` / `X` / `C` if they want a long putt or a finesse drive).

| Mode | Drag % | BH spread | FH spread | BH max | FH max | Notes |
|---|---|---|---|---|---|---|
| **Putt**  | 0–30%   | ±1°  | ±2°  | 25m | 22m | Wrist-only; can't spit basket |
| **Mid**   | 30–70%  | ±2.5° | ±2.5° | 55m | 50m | Equal hands |
| **Huck**  | 70–100% | ±5°  | ±3°  | 110m | 95m | BH = distance king; FH = accuracy |

(All numbers are tuning starting points; m is logical map units.)

UI: power meter is colored by mode (green / yellow / red) and labels the mode.

### 3.2 Forehand release point (visible difference)

In real play, FH releases from the player's right side, BH from the left.
We add a **player marker** at the lie — a small pill/arrow showing which way
the player faces, with the disc visibly offset:

```
          ●  (BH disc, released from left)
       \ /
        ◉   <- player avatar
       / \
          ●  (FH disc, released from right)
```

The throw originates from the disc offset, not from the lie center. Mechanical
effect: aim line begins at the offset point, which subtly changes geometry on
tight gaps (a real disc-golf consideration). Also: the disc icon spins visibly
clockwise for BH (RHBH convention) and counter-clockwise for FH.

### 3.3 Hyzer/anhyzer — make it pop

Three layered visualizations:

1. **Disc icon tilts** — drawn as an ellipse, the major axis tipped by the
   hyzer angle. Hyzer = left edge down (foreshortened), anhyzer = right edge down.
2. **Tilt gauge above disc** — a horizon-style indicator (a bar that visibly
   rotates like an airplane attitude indicator), much more legible than the
   current cyan dot.
3. **Curved aim preview** — *the killer feature*. While the player is dragging,
   we run the actual flight simulation forward in fast-forward and draw a
   ghost trajectory. The player literally sees the predicted curve before
   releasing. This trivializes learning hyzer-flip, flex shots, etc.

Q/E hold: keys now auto-repeat with continuous adjust (small step per frame
while held). Tap = small nudge, hold = smooth sweep.

### 3.4 Continuous course / camera

The fix for "every hole is a tiny screen":

- **Logical world per hole**: 2400 × 1400 px (≈ ⅔ of a real 18-hole layout).
- **Viewport**: 1920 × 1080 (configurable, see §3.7).
- **Camera follows the disc** during flight, with a small lookahead.
- **At rest**, camera centers on the midpoint between disc and basket so both
  are visible.
- **Mini-map** in the corner shows the whole hole + disc + basket.

This makes 200m holes legible without making the disc a 2-pixel dot.

(Stretch goal: a single continuous course where holes are connected. Probably
post-v0.3.)

### 3.5 Obstacles & environment (revised — surface model)

**Key insight (from playtest review):** obstacles and surfaces are two different
things. A tree blocks the disc *in flight*. Grass and sand affect what happens
*after the disc lands*. Treating them uniformly was a category error in the
original design.

#### In-flight obstacles (only one type in v0.3)

| Type | Color | Interaction |
|---|---|---|
| **Tree** | Dark green | Hard stop, lose 85% velocity |

Rocks, walls, and bushes are cut from v0.3 — see "Cut and why" below.

#### Surface zones (affect rolling after landing, not in-flight)

| Zone | Color | Roll friction | Penalty |
|---|---|---|---|
| Fairway | Light green | 1.0 (baseline) | — |
| Short grass | Yellow-green | 0.7 | — |
| Rough / tall grass | Dark olive | 0.25 (stops fast) | — |
| Sand | Tan | 0.15 (almost no roll) | — *(real disc-golf rule: sand is hard lie, not OB)* |
| Water | Blue | — | **+1 stroke, drop at last in-bounds crossing** |

Water is the only penalty zone in v0.3. Explicit OB (course-defined red lines)
is deferred to v0.4 to keep the surface vocabulary tight.

#### New core mechanic: post-landing roll

The disc no longer stops the instant `speed < STOP_SPEED`. Instead it enters
a roll phase:

```
on_land():
    # Roll speed depends on landing velocity AND landing tilt.
    # A flat disc rolls long; a spike-hyzer disc lands almost dead.
    roll_speed = land_velocity * (1 - 0.6 * |hyzer_at_release|)
    # Surface multiplier applied per frame as drag = base_drag / surface_friction
    enter_roll_state()
```

During roll: no lateral forces (turn/fade/hyzer don't apply), only directional
friction. Each frame samples the current surface under the disc and adjusts
drag. Disc stops when speed < ROLL_STOP_SPEED. **Roll can complete a putt**:
if the disc rolls through the basket capture radius, it counts as in.

Gameplay implications:
- Spike-hyzer = pinpoint landing (no roll) — useful near tight pin positions.
- Flat throw on fairway = bonus distance from roll-out (rewards risk).
- Landing in rough = dies fast (predictable but short).
- Roll-into-water is a real risk — pick your line.

#### Cut and why (v0.3 scope clarification)

| Cut | Reason |
|---|---|
| Rock bounce | No realistic forest/park use case; bounce physics feel arcade |
| Wall reflection | Belongs in a future "urban" theme — no v0.3 hole needs it |
| Bush pass-through | Just a surface-roll modifier in disguise; folded into "rough" |
| Explicit OB zones | Water alone covers the penalty story for v0.3 |

### 3.6 Basket spit-out

```
on_basket_hit(speed):
  if mode == PUTT or speed < BASKET_CATCH_SPEED:
	catch()
  else:
	spit_out_chance = (speed - CATCH_SPEED) / (HOT_SPEED - CATCH_SPEED)
	if random() < spit_out_chance:
	  deflect_velocity(speed * 0.4, random_perpendicular)
	  sfx_rim_out
	else:
	  catch()
```

So full-power drives have ~40% spit-out chance. Putts always catch.
This rewards finesse on approach shots — a major real-world skill.

### 3.7 Screen / window

- Default viewport bumped to **1920 × 1080**.
- Project setting changed to `disabled` stretch with manual layout, so
  the player can resize the window.
- World coords stay logical (2400 × 1400 per hole); camera handles
  whatever the viewport happens to be.

### 3.8 Wind upgrade

- **Crosswind drift on neutral discs**: a small lateral push on flat (no hyzer,
  speed-stable) discs, increasing with crosswind component. Currently we model
  wind as straight velocity add — this is correct for tail/head/cross but
  doesn't account for "stable disc holds line better in wind." We add a stability
  factor: a disc's resistance to wind = `1 - 0.2 * |turn|`. Understable discs
  drift more.
- **Wind variation**: optional gust system later. For v0.3, keep constant.
- **Visualization**: an animated grass-sway or particle drift on the field so
  wind is *felt* visually, not just labeled.

## 7. Open Design Questions — RESOLVED

All four questions confirmed (2026-05-24):

1. **Auto mode by default, manual override** (Z/X/C) — drag length picks Putt/Mid/Huck automatically; player can force a tier when desired.
2. **Predicted trajectory ON by default**, hideable via Pro Mode setting.
3. **Water penalty: drop at crossing point** (PDGA standard).
4. **Continuous course punted to v0.4** — per-hole maps with camera give 80% of the feeling for 30% of the work.

Plus from the obstacle/surface discussion: only **trees** as in-flight obstacle in v0.3, surface zones (fairway / short grass / rough / sand) only affect post-landing roll, **water** is the sole penalty zone. See §3.5.
